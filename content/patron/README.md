# Контент по экранам и попапам

Текущая страница: `app/page.tsx` → `app/components/patron/PatronPage.tsx`. Desktop и mobile используют одни и те же файлы. Каждый экран и его попапы получают тексты напрямую из своего модуля; общего словаря `text001…` больше нет.

| Файл | Экспорт | Где отображается |
| --- | --- | --- |
| `ui.ts` | `ui`, `contacts`, `navigation`, `sectionLabels`, `imageDimensions` | Общие элементы: меню, футер, логотип и сопровождающие его тексты, контакты, ссылки документов, служебные подписи и символы. Здесь же общие размеры изображений. |
| `hero.ts` | `hero` | Первый экран: заголовок с анимированным `word`, описание, цепочка работы, подписи раскрытия и сворачивания съёмки. |
| `lead.ts` | `lead` | Экран заявки и попап «Обсудить проект»: поля, `formats`, `scales`, пояснения к звонку, валидация, отправка, ошибка, подтверждение и связь с кейсом. |
| `about.ts` | `about` | Экран «О нас»: `manifesto`, три принципа и их описания. Цвета фрагментов манифеста стоят рядом с текстом. |
| `stats.ts` | `stats` | Экран статистики: доступное описание изображения, значения и подписи всех четырёх показателей. |
| `servises.ts` | `services`, `servicesCopy` | Экран услуг, обзор и все состояния от «Стратегия» до «Аналитика»: названия, описания, списки, CTA и навигационные подписи. Имя файла соответствует принятому в задаче `servises`. |
| `cases.ts` | `cases`, `casesCopy` | Экран кейсов и все попапы: карточки, задачи, решения, показатели, примечания, видео-заглушки и переход к заявке. |
| `process.ts` | `phases`, `processCopy` | Экран процесса и все попапы этапов: сроки, цели, состав работ, результаты, коммуникация и навигация. |
| `visitor.ts` | `visitorCopy`, `defaultLocation`, `locationCityVersion`, тип `VisitorLocation` | Cookies, определение города и местное время. Файл при реорганизации не изменён. |
| `seo.ts` | `seo`, `structuredData` | Заголовок вкладки и поиска, description, Open Graph/Twitter, canonical-домен и данные организации. Заголовок и полное описание связаны с текущими `hero.ts` и `ui.ts`; короткий текст карточки редактируется здесь. |
| `types.ts` | Типы записей и формы | Общие технические типы; отображаемых текстов нет. |

## Как редактировать

```ts
import { hero } from "@/content/patron/hero";
import { lead } from "@/content/patron/lead";
import { services, servicesCopy } from "@/content/patron/servises";
import { ui, contacts } from "@/content/patron/ui";
```

- Большой текст раздела «О нас» — `about.ts → about.manifesto`.
- Слово «стратегии» на первом экране — `hero.ts → hero.word`.
- Форматы события и количество гостей — `lead.ts → lead.formats`, `lead.scales`. Масштаб отображается в выпадающем списке.
- Названия в меню, заголовках разделов и футере — `ui.ts → sectionLabels`; порядок меню — `navigation`.
- Контакты редактируются в `contacts`. Telegram в сообщениях формы и футере подставляется из него.

Смысл и значения текстов при переносе сохранены. Общие кнопки вроде «Обсудить проект», «Закрыть» и ссылки на политику остаются в `ui.ts`; специфичные тексты и состояния формы находятся в `lead.ts`.

Город посетителя и часы динамические. Москва в копирайте футера относится к агентству. Регистр надписей может меняться через CSS. Некоторые строки видны только в открытом меню, попапе, выпадающем списке или определённом состоянии формы; alt/aria-подписи предназначены для доступности.

## Переносы слов и чисел

При отображении применяется `app/lib/typography.ts`: слова из 1–2 букв и числа связываются со следующим словом неразрывным пробелом. Последнее слово или число абзаца/отдельного фрагмента может стоять в конце строки. Явные переводы строк сохраняются. В манифесте правило работает и между фрагментами разного цвета; перед ссылкой на политику короткое «по» остаётся рядом со ссылкой.

В TS-файлах оставляйте обычные пробелы: форматирование добавляется в JSX через `typography(...)`. Значения полей, вариантов формы, ссылки и отправляемые данные не преобразуются. При добавлении нового отображаемого текстового фрагмента используйте этот же помощник. Для фрагмента, за которым следует продолжение в соседнем inline-элементе, предусмотрен `typography(text, true)`.

## Поиск и карточки ссылок

`seo.ts` используется в `app/layout.tsx`, `app/manifest.ts`, `app/robots.ts` и `app/sitemap.ts`. Домен `https://ptrn.pro` взят из SEO-спецификации. Фирменный бейдж — `public/og-image.jpg` (1200×630), иконки — `public/favicon.svg`, `favicon-32.png`, `apple-touch-icon.png`, `icon-512.png` и `app/favicon.ico`.

После изменения текста/слогана, фотографии первого экрана или знака запустите `npm run seo:assets`, чтобы пересобрать изображение, иконки и локальные desktop/mobile-превью. Генератор использует текущие импорты и локальные шрифты. Проверка `npm run seo:check` сверяет изображение со снимком входных данных и проверяет метатеги через работающий сайт. Для другого адреса используйте `PATRON_BASE_URL`.

Превью для просмотра: `docs/patron-seo/preview.html`. Подробности и проверки: `docs/patron-seo/README.md`. Это локальные макеты карточек, а не дополнительный раздел одностраничника.

## Заменённые файлы

`copy.ts`, `site.ts`, `services.ts`, `phases.ts` удалены, их импорты заменены. Одноразовый генератор `scripts/migrate-patron.cjs`, создававший прежнюю структуру, также удалён. Не восстанавливайте эти файлы как параллельный источник текстов.

Старые `app/lib/content.ts`, `app/lib/ui-texts.ts`, `app/components/Hero.tsx` и `PatronHome.tsx` не подключены к текущей главной странице и не являются источниками её текстов.

## Проверка

`node scripts/patron-copy-check.cjs` сверяет тексты с интерфейсом на ширинах 1440 и 390: все услуги, кейсы, этапы, меню, форму и настройки посетителя. Проверка отправки использует перехват API и не отправляет настоящие заявки. Результаты: `docs/patron-copy/results.json`.
